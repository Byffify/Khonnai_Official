# Khonnai Home MVP

HTML, CSS และ JavaScript ล้วน สร้างจาก `../design/revisions/audit-fixes-v1/khonnai-home-v1.figcraft` โดยแยกจากไฟล์ออกแบบและสไลด์เดิมทั้งหมด ไม่มีขั้นตอน build และไม่มี animation

## เปิดใช้งาน

เปิด `index.html` ด้วย Chrome / Edge ได้โดยตรง หรือรันจากโฟลเดอร์นี้:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

แล้วเปิด http://127.0.0.1:4173

ข้อมูลเก็บด้วย localStorage แยกตามเบราว์เซอร์และ origin ดังนั้นการเปิดด้วย file URL กับ localhost จะใช้ข้อมูลคนละชุด เมนูบนหน้าโฮมมีปุ่มส่งออก JSON สำรองและเริ่มข้อมูลตัวอย่างใหม่ การส่งออกยังไม่มี flow นำเข้ากลับ

## Flow ที่ทำแล้ว

- โฮม: ยอดรายได้ของวันที่ปัจจุบัน รายการรอรับของ และสินค้าใกล้หมด
- สต็อก: ค้นหาชื่อ/รหัส กรองหมวด เฉพาะที่มีของ เรียงลำดับ ดูรายละเอียด และอัปเดตจำนวน
- จัดการสินค้า: แก้ข้อมูล ปิด/เปิดการขาย ลบพร้อมยืนยัน และป้องกันลบสินค้าที่ยังมีการจอง
- สอนใช้งาน: เปิดแอปครั้งแรกมี modal และชี้ปุ่มหลัก 3 ขั้น เปิดซ้ำได้ที่ ตั้งค่า → โหมดสอนใช้งาน
- เพิ่มสต็อก: เลือกรุ่นเดิมหรือรุ่นใหม่ ส่วนถ่ายบิลยังรอระบบอ่านบิล
- เพิ่มรุ่น: อัปโหลดรูป ชื่อ รหัส หมวด จำนวนต่อแพ็ก ราคา ไซซ์ สี จำนวนแต่ละช่อง เพิ่มไซซ์/สี ใส่จำนวนเท่ากัน และตรวจข้อมูลก่อนบันทึก
- ออกบิล: เลือกสินค้า เพิ่ม/ลดจำนวน นำออกด้วยจำนวน 0 เปลี่ยนลูกค้า/ช่องทาง ใส่ส่วนลด ยืนยันและตัดสต็อกครั้งเดียว
- สินค้าใหม่ที่มีจำนวนแยกไซซ์/สี: เลือกจำนวนแยกในหน้าต่างจำนวน ตัดจากช่องที่เลือก และแก้สต็อกแยกในหน้าต่างอัปเดตสต็อก
- จอง: กันสต็อก แก้ลูกค้า/ช่องทาง/รายการ/ส่วนลด ยกเลิกแล้วคืนจำนวน รับของแล้วออกบิลโดยไม่ตัดสต็อกซ้ำ
- ประวัติ: บิลใหม่เปิดดูได้ ข้อมูลตัวอย่างเดิมแสดงตามต้นแบบและระบุว่าเป็นตัวอย่าง
- บิล: เปิดหน้าต่างพิมพ์ของเบราว์เซอร์เพื่อพิมพ์หรือเลือก Save as PDF

## ข้อมูลตัวอย่างและขอบเขต

- บิลร่างเริ่มต้น 2 × 240 + 1 × 120 + 2 × 280 = **1,160 บาท** ปรับ B-220 เป็น 3 แพ็กได้ **1,440 บาท**
- ยอดเดิม 12,450 บาท / 18 บิลเป็นข้อมูลตัวอย่างวันที่ 31 ต.ค. 2569 เท่านั้น บิลที่สร้างเพิ่มรวมตามวันที่ในเขตเวลา Asia/Bangkok
- สต็อกเริ่มต้นยึดรายการในหน้าเลือกสินค้า ไม่ผสม A-301 จากดีไซน์อีกชุด สินค้าลูกไม้ตัวอย่างใช้รหัส A-302 เพื่อให้เพิ่ม A-301 ตาม flow ได้
- แผงเติมของคำนวณจากจำนวนจริงใน MVP: 3 รุ่นขาดรวม 16 แพ็ก แทนตัวเลขเตรียมไว้ 25 แพ็กในต้นแบบซึ่งอ้างถึงตัวเลือกไซซ์/สีที่ไม่มีข้อมูลครบ
- สินค้าเดิมในต้นแบบมีเฉพาะจำนวนรวมต่อรุ่น ส่วนสินค้าใหม่รองรับจำนวนแยกไซซ์/สี รูปสินค้าเดิมใช้ placeholder ตามต้นแบบ
- ช่องทาง LINE เป็นเพียงข้อมูลบนบิล ไม่มีการส่งข้อความหรือเชื่อมต่อ LINE
- ไม่มี backend, login, synchronization ข้ามอุปกรณ์ หรือการรับประกันธุรกรรมพร้อมกันหลายแท็บ ใช้ทดลองในเบราว์เซอร์เดียว
- ข้อมูลจะหายเมื่อเคลียร์ browser storage โควตาเต็มจะมีข้อความแจ้งให้ส่งออกสำรอง
- ยังไม่ได้ทดสอบเครื่องพิมพ์จริง มือถือจริง หรือ production deployment

## ไฟล์

- `index.html`: จุดเปิดแอป
- `app.css`: stylesheet เดียว ค่าทั้งหมดถอดจาก node ต้นฉบับ mobile-first ไม่มีกรอบมือถือ พร้อม Google Sans แบบ local
- `app.js`: views, state, localStorage และ flow ธุรกรรม
- `settings.js`: หน้าตั้งค่าและหน้าย่อย, PromptPay QR (EMVCo + CRC16)
- `assets/vendor/qrcode.js`: qrcode-generator 1.4.4 (MIT, Kazuhiko Arase) เก็บในโปรเจกต์ ไม่โหลดจากเน็ต
- `assets/design-*.png`: โลโก้ที่แยกจาก archive ต้นแบบ
- `assets/revenue-waves.svg`: ลายการ์ดจาก control points ของเวกเตอร์ต้นฉบับ
- `assets/fonts/`: Google Sans และ SIL Open Font License
- `verification/`: browser checks และภาพหน้าจอ

## อัปเดตความตรงกับต้นแบบ (รอบ 2)

- เอากรอบ iPhone ออก แอปเต็มจอมือถือ (mobile-first) จอกว้างตั้งแต่ 600px แสดงเป็นคอลัมน์กลาง 480px
- ใช้ Google Sans ทั้งแอป ขนาดตัวอักษร สี ระยะ มุมโค้ง และเงาถอดจาก `khonnai-home-v1.figcraft` ทุกหน้า (27 frames)
- ข้อมูลตัวอย่างตรงกับต้นแบบ: รายได้วันนี้ ฿12,450 / 18 บิล (ผูกกับวันที่ปัจจุบันเสมอ บวกบิลที่ออกจริง), ของขาด 25 แพ็ก 3 ตัวเลือก (คิดรายไซซ์/สี), รายการจอง 3 ออเดอร์ 16 แพ็ก ฿4,240 พร้อมเวลา "วันนี้ / เมื่อวาน"
- แผงต้องเติมของคิดจากจำนวนรายไซซ์/สี: สินค้าที่เพิ่มใหม่ใช้จำนวนจริงในตาราง สินค้าเดิมใช้ข้อมูลตัวอย่างรายตัวเลือกของ A-215 และ A-102 สินค้าที่เก็บเป็นยอดรวมอย่างเดียว (เช่น P-310) ไม่แสดงในแผงนี้ และยอดรายตัวเลือกตัวอย่างไม่ลดตามการขาย
- เปลี่ยน storage key เป็น `khonnai-home-mvp-v2` ข้อมูลเก่าในเบราว์เซอร์จะเริ่มใหม่ด้วยชุดตัวอย่าง
- เพิ่มหมายเหตุบนบิล (แสดงบนบิลเงินสด) และ error รายช่องในฟอร์มเพิ่มรุ่น
- สคริปต์ใน `verification/` และภาพหน้าจอเดิมอ้างอิงเลย์เอาต์กรอบมือถือรอบก่อน ยังไม่ได้อัปเดตตามรอบนี้

## แอปว่าง (ไม่มีข้อมูลตัวอย่าง)

- เริ่มต้นไม่มีสินค้า บิล รายการจอง หรือบิลร่าง ตัวเลขทุกตัวคำนวณจากข้อมูลที่ผู้ใช้เพิ่มเองเท่านั้น
- ลบยอดตัวอย่าง ฿12,450 / 18 บิล, ประวัติขายตัวอย่าง และข้อมูลของขายรายตัวเลือกตัวอย่างออก
- หน้าสินค้าและออกบิลที่ยังว่างมีปุ่ม "เพิ่มรุ่นใหม่" ประวัติการขายแสดง "ยังไม่มีบิล"
- เมนู "ล้างข้อมูลทั้งหมด" แทน "เริ่มข้อมูลตัวอย่างใหม่"; storage key เป็น `khonnai-home-mvp-v3` (ข้อมูลเก่าในเบราว์เซอร์ไม่ถูกโหลด)
- ไม่มีชื่อร้านตัวอย่าง: แสดง "ร้านของฉัน" จนกว่าจะตั้งชื่อจากเมนู "ตั้งชื่อร้าน" ชื่อนี้ใช้บนหน้าโฮม บิล และชื่อแท็บ ช่องผู้รับเงินบนบิลเว้นว่างไว้ให้เซ็น

## รอบ 3: ตั้งค่า + แก้ตาม mockup ล่าสุด

ต้นแบบ: `design/khonnai-home.figcraft` (41 frames)

**แก้หน้าเดิม**
- ปุ่ม "ประวัติการขาย" สูง 44px, เมนูด่วน "สต็อกสินค้า", หัวหน้าสต็อก "สต็อกสินค้า", ปุ่ม "ยืนยันการออกบิล", ตัวเลขในตารางไซซ์/สี 18px, ยอดในการ์ดจอง 18px
- หน้าโฮมร้านใหม่ "เริ่มใช้งานใน 2 ขั้น", สต็อกว่าง "ยังไม่มีสินค้าในร้าน", โหมดค้นหาพร้อม "พบ N รุ่น"
- อัปเดตสต็อกแล้วอยู่หน้าเดิม พร้อมแถบแจ้ง "เลิกทำ"
- ปุ่มออกบิล/จองแสดง "กำลังออกบิล…" และกันกดซ้ำ
- แผ่นเลือกลูกค้า (ลูกค้าหน้าร้าน, ลูกค้าประจำจากบิลและการจองจริง, เพิ่มลูกค้าใหม่ชื่อ + เบอร์)
- ยืนยันยกเลิกการจองแบบกล่องกลางจอ
- เมนู ☰ เป็น drawer มีจำนวนการจองที่รออยู่ และทางเข้า "ตั้งค่า"

**หน้าตั้งค่า** (เข้าจาก ☰ → ตั้งค่า) ค่าทั้งหมดเก็บใน `state.settings` ใน localStorage ชุดเดิม
- ข้อมูลร้าน: โลโก้ ชื่อ เบอร์ ที่อยู่ LINE ID → หน้าโฮม, drawer, หัวบิล, ชื่อแท็บ
- เลขพร้อมเพย์: เบอร์มือถือหรือเลขบัตร (ตรวจ checksum) + ชื่อบัญชี + สวิตช์แสดง QR บนบิล → QR พร้อมยอดเงินบนบิลเงินสด
- หัวบิลเงินสด: ตัวอย่างหัวบิล + เลขที่บิลถัดไป (ห้ามน้อยกว่าเลขที่ออกไปแล้ว) → เลขบิลถูกบันทึกไว้ในบิลแต่ละใบ
- เตือนเมื่อเหลือต่ำกว่า: ค่าเริ่มต้น + ตั้งรายรุ่น → การ์ด "ต้องเติมของ"
- หมวดสินค้า: เพิ่ม/เปลี่ยนชื่อ (สินค้าเดิมย้ายตาม)/เลื่อนลำดับ/ลบ (ถ้ามีสินค้าต้องเลือกหมวดปลายทางก่อน) → ชิปหน้าสต็อก, แถบหมวดหน้าออกบิล, ฟอร์มเพิ่มรุ่น
- เทมเพลตสี: 16 สีตามต้นแบบ แก้/เพิ่ม/ลบได้ → จุดสีและคำแนะนำในฟอร์มเพิ่มรุ่น
- ข้อมูลในเครื่อง: ส่งออก / นำเข้า (ตรวจไฟล์และยืนยันก่อนแทนที่) / ล้างข้อมูลทั้งหมด (ไม่มีในต้นแบบ ย้ายมาจากเมนูเดิม)
- state ทุกหน้าที่มีฟอร์ม: error ใต้ช่อง, "กำลังบันทึก…", และข้อความเมื่อพื้นที่เก็บข้อมูลเต็ม

**ยังต้องมีระบบบัญชีออนไลน์ (แสดง "รอข้อมูลจริง")**
- ผู้ใช้และสิทธิ์, เชิญผู้ช่วยร้าน (QR/ลิงก์ LINE ปิดไว้), แพ็กเกจ (ราคาตามต้นแบบ ปุ่มอัปเกรดปิดไว้), ออกจากระบบ (กล่องยืนยันมี แต่ยังไม่มีการเข้าสู่ระบบ)
- หน้า "สิทธิ์ของผู้ใช้" ในต้นแบบยังไม่ได้ทำ เพราะยังไม่มีผู้ใช้คนอื่นให้กดเข้าไป

**ต่างจากต้นแบบโดยตั้งใจ**
- ปุ่มในตัวเลือกแบบแบ่งช่อง (หน้าร้าน/LINE, สีเดียว/คละสี, แท็บ) สูง 44px ตามกติกาปุ่ม แทน 38–40px ในต้นแบบ
- หมวดสินค้าเลื่อนลำดับด้วยปุ่ม "เลื่อนขึ้น/ลง" ในแผ่นแก้หมวด แทนการกดค้างลาก
- โหมดค้นหาวางช่องค้นหาไว้ชิดบน แทนการเว้นที่ว่างเท่าแถบหัว

**ตรวจแล้ว** (Chromium, 393px และ 320px): ตัดสต็อกครั้งเดียวตอนขาย, การจองกันสต็อก, ออกบิลจากใบจองไม่ตัดซ้ำ, ยกเลิกการจองคืนสต็อก, เลขบิลต่อจากค่าในตั้งค่า, ชื่อร้าน/ที่อยู่/QR ขึ้นบนบิล, เลิกทำการอัปเดตสต็อก, ปุ่มทุกปุ่มสูง ≥44px, ไม่มีการเลื่อนแนวนอนที่ 320px; payload พร้อมเพย์ตรวจโครงสร้างและ CRC16 (ค่ามาตรฐาน "123456789" = 29B1) แต่ยังไม่ได้สแกนจ่ายจริงด้วยแอปธนาคาร
