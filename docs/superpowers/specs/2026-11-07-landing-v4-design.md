## เป้าหมาย

ให้ landing น่าเชื่อถือ มีชีวิตชีวา และพูดตรงกับสิ่งที่แอปทำได้จริง คงการ์ดล้อมหัวข้อตามแนว fastwork.com ซึ่งเป็นความตั้งใจของทีม โดยยืมเฉพาะองค์ประกอบ เพิ่มความอุ่นด้วยสีส้มและลูกเล่นที่มาจากของ Khonnai เอง ได้แก่ เส้นคลื่นจากการ์ดรายได้ และบิลเงินสด

**เกณฑ์สำเร็จ:** พื้นไล่สีเบาตามดีไซน์ ไม่มีข้อความไล่สี การ์ดลอย หรือวงแหวนหมุน ไม่มีข้อความ placeholder บนหน้าสาธารณะ ทุกปุ่มและลิงก์ไปถึงปลายทางจริง และหน้าตาตรงกับดีไซน์ที่ 375, 768 และ 1440px

## นอกขอบเขต

- เนื้อหาแพ็กเกจ (รอทีมตัดสินใจ ระหว่างนี้ landing กับหน้าแพ็กเกจในแอปยังพูดไม่ตรงกัน)
- ตัวเลือกภาษา (คงไว้เหมือนเดิม)
- ลำดับ section

## 1. Hero

- พื้นไล่สีเบา: ขาว + วงฟ้าอ่อนด้านซ้าย + วงพีชด้านขวา สีเข้มสุด 20% ใช้ `radial-gradient` ใน CSS แทนก้อนสีเบลอเดิม (`Hero.tsx:266-269`) เพื่อให้เบาบนมือถือ และวงต้องกลมนุ่มทุกขนาดจอ
- การ์ด 12 ใบ กรอบแบบเดียวกัน รูปอยู่บนและคำบรรยายอยู่ล่าง ไม่เอียง ล้นขอบจอซ้ายขวาตามดีไซน์
- **บิลเงินสดเป็นใบเด่นใบเดียว:** ใหญ่กว่าใบอื่น มีเงา และคำบรรยายสีเข้ม ส่วนใบอื่นไม่มีเงาและคำบรรยายสีเทา
- **ตรา "ตัดสต็อกแล้ว":** สี `#C2410C` บนพื้นขาว 85% เอียง -8° อยู่บนแถวว่างของบิล ห้ามทับตัวเลข ใช้กับใบเด่นเท่านั้น
- การ์ดที่เป็นรูป AI มีคำว่า "ภาพประกอบ" ในคำบรรยายตาม `ILLUSTRATION` เดิม
- เอาการหมุนเข้า, การลอย, การแตกกระจายตอนเลื่อน และวงแหวนส้มเรืองแสงออก (`OrbitCard`, `Lift`, `.hero-float`)
- ใช้การปรากฏตัวครั้งเดียว เป็นการจางสั้น ๆ พร้อมกันทั้งหน้า ยกเว้นบิลตามส่วนที่ 3
- หัวข้อน้ำหนัก Medium สีเข้มสีเดียว ขนาด 52px บนเดสก์ท็อป และ 34px บนมือถือ
- คำที่หมุนคงไว้ เป็น Google Sans น้ำหนัก 600 สี `#E2640F` ไม่มีเอฟเฟกต์เบลอ
- **เส้นคลื่นส้ม `#FF8032`** ใต้คำที่หมุน ความกว้างจองตามคำยาวสุด และเส้นต้องไม่ทับบรรทัดถัดไป
- จอกว้าง: จองความกว้างเท่าคำที่ยาวที่สุด เพื่อไม่ให้ข้อความรอบข้างขยับ
- มือถือ: ล็อกหัวข้อ 3 บรรทัดเพื่อไม่ให้ตัดบรรทัดใหม่เมื่อคำเปลี่ยน
- ต่ำกว่า 1280px ไม่มีที่ล้อมหัวข้อ จึงใช้แถวการ์ด 3 ใบใต้ปุ่มตามดีไซน์ Tablet และมือถือ และต้องเห็นได้โดยไม่รอแอนิเมชัน
- `prefers-reduced-motion`: หยุดที่คำแรกและไม่มีการจาง

**ดีไซน์ครอบคลุม:** 1440, 768 และ 375px ความกว้างระหว่างนั้นต้องตรวจตอนทำจริง โดยเฉพาะ 1280-1399px ที่การ์ดอาจชิดข้อความ

## 3. แอนิเมชันบิล

บิลใบเด่นบน hero พิมพ์ออกมาครั้งเดียวเมื่อเข้าจอ ต้นแบบอยู่ที่ `D:\Slide_MileStone2\design\preview\bill-print-prototype.html` และลำดับภาพอยู่ในเฟรม `Landing v4 — บิลพิมพ์ (motion)`

| ช่วงเวลา | สิ่งที่เกิด |
|---|---|
| 0-720ms | กระดาษไหลลงด้วย `clip-path` และ `transform` ด้วย `cubic-bezier(.22,1,.36,1)` |
| 760-980ms | ตราจางเข้าและย่อจาก 1.15 เป็น 1 ไม่มีการเด้ง |

- เริ่มเมื่อเห็นบิล 35% ด้วย `IntersectionObserver` และเล่นครั้งเดียวต่อการเปิดหน้า
- จองพื้นที่ของบิลไว้ก่อน เพื่อไม่ให้เลย์เอาต์ขยับ
- `prefers-reduced-motion`: แสดงบิลและตราทันที
- ถ้า JavaScript ไม่ทำงานหรือโหลดช้า ต้องไม่เห็นพื้นที่ว่างแทนบิล
- ต้องลองจังหวะบนเครื่องจริง เพราะการตรวจรอบออกแบบยืนยันได้แค่หน้าจอสุดท้าย

## 4. ฟอนต์

ใช้ Google Sans ฟอนต์เดียวเหมือนแอป

- `GoogleSans-Latin.woff2` เป็นชุดตัดที่**ไม่มีอักษรไทย** จึงต้องสร้าง woff2 ใหม่ที่มีไทยกับ Latin น้ำหนัก 400-700 และใช้ไฟล์ร่วมแนวทางเดียวกับแอป
- ลบ `@fontsource/mali`, `--font-hand`, `NotoSansThai.woff2` และ `@font-face` ของ Noto

## 5. ภาพหน้าจอ

- ถ่ายภาพใหม่จากแอปจริงหลังงานแอปเสร็จ ด้วยข้อมูลตัวอย่างชุดเดียวกัน แทนไฟล์ใน `landing/src/assets/screens/`
- ถ่ายหน้า**เพิ่มรุ่นใหม่**จริงด้วย ดีไซน์ใช้ภาพสต็อกแทนชั่วคราว
- ภาพหน้าจอต้องมีแถบล่างใหม่และหัวหน้า "ขาย"

## 6. หน้านโยบาย (มีด่านอนุมัติ)

ร่างเนื้อหาอยู่ในไฟล์ดีไซน์ ทั้งนโยบายความเป็นส่วนตัวและข้อกำหนดการใช้งาน ทุกจุดที่ยังไม่รู้เขียนในวงเล็บ `[...]`

**ห้ามขึ้นเว็บจนกว่าทีมและผู้เชี่ยวชาญกฎหมายจะยืนยันเนื้อหาครบ และไม่เหลือวงเล็บ**

ระหว่างรอ:
- เอาลิงก์ `#` ที่ไปไม่ถึงไหนออกจาก footer (`content.ts:141`, `Sections.tsx:366`)
- เตรียมโครงหน้าได้ แต่ห้ามลิงก์ถึงหรือ deploy เนื้อหาร่าง
- เมื่ออนุมัติแล้วค่อยเพิ่มหน้าและลิงก์ใน footer ตามดีไซน์ พร้อมอัปเดต `sitemap.xml`

**ข้อความที่ต้องยืนยันก่อนใช้:** "ไม่ส่งข้อมูลไปยังเซิร์ฟเวอร์" อิงจากโค้ดปัจจุบันที่ไม่มีระบบบัญชีและไม่พบสคริปต์ analytics ต้องตรวจซ้ำก่อนขึ้นเว็บ

## 7. ด่าน unslop (บังคับ)

งานทุกขั้นต้องใช้ skill `unslop` เต็มรูปแบบ ก่อนจบงานต้องไล่เช็กลิสต์ท้าย skill แล้วรายงานทุกข้อ รวมข้อที่ไม่ผ่าน

**ข้อยกเว้นที่ผู้ใช้เลือกเอง (คงไว้):** การ์ดล้อมหัวข้อแนว fastwork (unslop ชอบ visual เดียว), navbar และการ์ดกระจกบนรูป, พื้นไล่สีเบาบน hero กับส่วนราคา (unslop ไม่แนะนำแสงสีหลังเนื้อหา), พื้นไล่กรมท่าในบล็อกปิดท้าย และน้ำเงินแบรนด์

**ขอบเขตของข้อยกเว้น:** กระจกใช้เฉพาะ navbar และบนรูป ห้ามใช้กับการ์ดบนพื้นเรียบ ส่วนพื้นไล่สีใช้เฉพาะ 3 ส่วนที่ระบุ

**การใช้สีส้ม:** `#FF8032` สำหรับเส้นและพื้นเท่านั้น, `#E2640F` สำหรับหัวข้อใหญ่, `#C2410C` สำหรับตรา และ `#9A4A0C` สำหรับตัวอักษรเล็ก

**ทุกส่วนที่แก้ต้องมี:** hover และ focus ในโทนเดียวกับ palette, `tabular-nums` บนตัวเลข, easing เดียว และการเคลื่อนไหวที่ใช้แค่สี พื้น ความโปร่งใส และ transform (ฟีเจอร์เลิกใช้ animation ความสูงแถว)

**ข้อกำหนดจากการตรวจ unslop ที่ผู้ใช้อนุมัติแล้ว:**

| เรื่อง | ข้อกำหนด |
|---|---|
| น้ำหนักตัวอักษร | ไม่เกิน 600 ทั้งหน้า |
| ขนาดตัวอักษร | ใช้เฉพาะ 14, 16, 18, 20, 24, 28, 34, 44, 52px |
| ปุ่ม | มุมโค้ง 12px ยกเว้นปุ่มและตัวเลือกภาษาใน navbar ที่อยู่ในแคปซูล |
| ป้าย "แนะนำ" | ข้อความเล็กสีอ่อนบนการ์ด Basic ไม่มีพื้น |
| ระยะห่าง | อยู่บนสเกล 4px |

## 8. การทดสอบ

1. `npm run build` ผ่าน รวม `tsc --noEmit`
2. ที่ 375, 768, 1280, 1440 และ 1680px เทียบกับดีไซน์ ไม่มี overflow แนวนอน และการ์ดไม่ทับข้อความ
3. คำที่หมุนทั้ง 3 คำไม่ทำให้เลย์เอาต์ขยับ
4. คลิกทุกปุ่มและลิงก์ ไม่เหลือลิงก์ `#` ที่ไม่ไปไหน
5. ค้นทั้งหน้าแล้วไม่พบ "รอข้อมูลจริง", "รอทีมยืนยัน" และ "เข้าสู่ระบบ"
6. เปิด `prefers-reduced-motion` แล้วไม่มีการเคลื่อนไหวต่อเนื่อง และบิลแสดงครบทันที
7. วัดความคมชัดจริงของข้อความบนจุดเข้มสุดของพื้นไล่สี, ตัวอักษรบนการ์ดกระจก และตรา
8. ลองบนมือถือจริงอย่างน้อย 1 เครื่อง เทียบน้ำหนักหน้าเว็บก่อนกับหลังเปลี่ยนฟอนต์ และดูจังหวะแอนิเมชันบิล
